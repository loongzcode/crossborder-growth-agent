| 项目 | 内容 |
| --- | --- |
| 产品名称 | CrossBorder Growth Agent |
| 产品定位 | 跨境电商多 Agent 经营决策系统 |
| 使用对象 | 跨境电商负责人、广告投手、选品与供应链人员、内容运营、财务与合规人员 |
| 当前状态 | 最终范围已确定，进入工程实施 |

## 2. 背景与问题

跨境电商经营数据分散在广告平台、店铺后台、订单系统、供应链表格和素材文件中。运营人员往往需要手工下载报表、复制字段、计算投产，再依靠经验解释异常。这会造成以下问题：

- 数据采集和字段整理占用大量重复劳动，且容易出现口径错误。
- ROAS、订单量等表面指标无法反映退款、物流、平台费和商品成本后的真实利润。
- 投放、选品、库存、内容和合规各自判断，缺乏统一证据链和冲突处理。
- 结论依赖个人经验，缺少可复现的诊断过程、历史回测与结果反馈。
- 高风险动作若直接自动执行，会带来预算损失和账号风险。

## 3. 产品目标

系统将广告、订单、商品、成本、库存、退款、评价、素材和政策数据统一治理，通过一个 Supervisor Agent 协调八个领域 Agent，输出有指标证据、风险说明和人工审批节点的经营建议。

### 3.1 业务目标

- 将“下载报表—整理表格—计算指标—解释异常”转化为自动同步或标准文件导入流程。
- 从 ROAS 分析升级到贡献利润、库存约束和退款影响下的综合经营判断。
- 对在售商品和候选商品执行可解释的选品评分、时间切分回测和冷启动测试设计。
- 将广告、客户、素材、利润供应和合规判断整合为可执行的优先级任务。
- 保留人工决策权，高影响动作必须审批，且所有运行过程可审计、可恢复。

### 3.2 AI 工程目标

- 使用状态化工作流完成动态路由、并行分析、失败恢复和人工中断。
- Agent 只负责需要语言理解、推理和决策整合的环节；计算、查询、校验和权限由确定性服务承担。
- 所有重要结论必须引用数据、公式、规则或政策证据，并携带置信度与缺失信息。
- 建立可复现评测集，分别评估路由、工具调用、计算、诊断、合规和选品排序。

### 3.3 非目标

- 不承诺替代 ERP、广告平台或完整 BI 仓库。
- 不在未审批情况下自动调预算、启停广告、发布商品或修改店铺配置。
- 不使用无法授权获得的数据，不绕过平台权限、验证码或访问控制。
- 不将开发样例数据或模拟连接器描述为真实商家线上数据接入。

## 4. 用户角色与权限

| 角色 | 核心任务 | 默认权限 |

| 经营负责人 | 查看全局经营健康度、审批预算和选品建议 | 查看全部经营数据、审批高影响动作 |

| 选品/商品运营 | 管理候选池、查看评分与冷启动计划 | 查看商品、需求、利润与合规信息 |
| 供应链/财务 | 维护成本、库存和物流参数，核对利润 | 编辑授权范围内的成本参数、查看利润明细 |
| 内容运营 | 分析素材、生成创意 brief | 查看脱敏受众信息和素材表现 |

## 5. 系统范围与 Agent 地图

### 5.1 Supervisor Agent

负责意图识别、任务拆解、领域路由、状态管理、并行调度、失败降级和信息补全。它不直接计算业务指标，也不绕过领域 Agent 或审批规则执行高影响动作。

### 5.2 Data Governance Agent

负责解释字段语义、识别未知列、处理口径冲突、生成字段映射建议和数据质量说明。实际解析、类型转换、唯一性校验与落库由确定性数据服务完成。

### 5.3 Ad Performance Agent

负责广告异常解释、漏斗诊断、归因窗口对比、预算情景分析和优化建议。基础指标由指标服务计算，Agent 不自行编造数据。

### 5.4 Product Intelligence Agent

负责候选商品发现、机会评分、竞品/需求信号解释、在售商品复盘、冷启动实验设计和时间切分回测结果解释。

### 5.5 Customer Insight Agent

负责受众分群解释、评价主题分析、退款原因归纳、需求与痛点识别、商品—人群适配分析。输出不得包含不必要的个人身份信息。

### 5.6 Creative Intelligence Agent

负责视频、图片、文案和落地页素材的结构化理解，结合曝光、点击、转化与频次判断素材疲劳，并输出可追溯的创意 brief。

### 5.7 Profit & Supply Agent

负责解释贡献利润、盈亏平衡 ROAS、库存覆盖天数、补货时点、物流与汇率风险，识别“高 ROAS 低利润”和“可投放但不可履约”等冲突。

### 5.8 Compliance & Risk Agent

负责平台政策、营销声明、禁限售、知识产权、数据完整性和动作风险检查。政策结论必须标注规则版本、来源和适用范围；无法确定时转人工审核。

### 5.9 Business Decision Agent

负责汇总领域输出、处理冲突、形成优先级队列、建议动作、预期影响、风险、责任人和复查时间。它是决策综合层，不替代审批人。

## 7. 核心业务流程

### 7.1 广告诊断流程

```text
同步/导入数据
  -> 确定性质量检查
  -> Data Governance Agent 解释口径与缺失
  -> Ad Performance Agent 诊断
  -> Profit & Supply / Customer / Creative 并行补充证据
  -> Compliance & Risk Agent 风险审查
  -> Business Decision Agent 汇总结论
  -> 人工审批或形成只读报告
  -> 结果与复查时间回写
```

### 7.2 选品流程

```text
候选池
  -> 字段与来源校验
  -> 硬约束过滤
  -> Product Intelligence Agent 解释排序
  -> Customer + Profit & Supply + Creative 并行评估
  -> Compliance & Risk Agent 审查
  -> Business Decision Agent 形成候选优先级与冷启动计划
  -> 人工审批
  -> 测试结果反馈与时间切分回测
```

### 7.3 工作流状态

任务状态统一为 `queued`、`running`、`waiting_for_data`、`waiting_for_approval`、`completed`、`failed`、`cancelled`。每次状态变化写入事件表；失败任务记录可重试性、错误类别和已完成节点。

## 9. 指标口径

核心公式由版本化指标服务实现：

- `CTR = clicks / impressions`
- `CPC = spend / clicks`
- `CVR = attributed_orders / clicks`
- `CPA = spend / attributed_orders`
- `ROAS = attributed_revenue / spend`
- `contribution_profit = net_revenue - product_cost - platform_fee - payment_fee - logistics_cost - tax - refund_loss - ad_spend`
- `break_even_roas = 1 / pre_ad_contribution_margin_rate`
- `inventory_cover_days = sellable_inventory / trailing_daily_sales_velocity`

分母为零、归因窗口不同、退款延迟和多币种换算必须显式处理，禁止静默填充造成伪精确结果。

## 10. 非功能需求

### 10.1 性能与可靠性

- 常规只读 API 在开发基准数据集下目标 P95 小于 500 ms；长耗时 Agent 工作流异步执行。
- 同步任务支持分页、限流、指数退避、幂等键、断点续传和死信记录。
- Agent 节点设置超时、重试和确定性降级；失败不得丢失已完成状态。
- 报告生成目标在数据准备完成后 2 分钟内返回；实际性能以压测报告为准。

### 10.2 安全与隐私

- 密钥仅通过环境变量或密钥管理服务注入，不写入代码、日志或仓库。
- 对平台连接使用最小权限和只读授权；写操作连接器默认关闭。
- PII 采用最小化采集、字段级脱敏、访问控制和导出审计。
- SQL 工具只允许参数化、只读、白名单表/视图和行级组织隔离。
- 日志不记录访问令牌、完整用户内容或未脱敏原始文件。

### 10.3 可观测性

- 记录请求 ID、工作流 ID、节点耗时、模型、token/成本、工具调用、重试、错误和结果状态。
- 提供数据新鲜度、同步成功率、Agent 成功率、审批等待时间和评测回归趋势。
- 模型、提示词、规则、指标公式和数据映射均版本化。

### 10.4 可维护性

- Python 后端、Agent 编排、领域逻辑、连接器和前端按边界解耦。
- Agent 输入输出使用严格结构化 Schema；禁止以自由文本作为跨节点唯一协议。
- 核心公式、权限、状态机和连接器契约具备自动化测试。

## 11. AI 评测与回测

### 11.1 基准评测集

建立不少于 80 条可复现案例，使用脱敏真实结构或人工构造数据，覆盖：

- 15 条意图识别和 Supervisor 路由案例。
- 15 条工具选择、参数提取和字段映射案例。
- 15 条指标计算与异常定位案例。
- 15 条跨领域诊断、冲突处理和证据引用案例。
- 10 条合规风险、拒答和转人工案例。
- 10 条选品排序与冷启动计划案例。

期望结果由人工规则、人工标注或确定性计算产生。评测不得仅依靠被测模型自己判断自己的回答。

### 11.2 指标

- 路由与工具选择：准确率、精确率/召回率、非法工具调用率。
- 结构化输出：Schema 通过率、必填字段完整率。
- 计算：精确匹配或允许误差范围内的数值准确率。
- 证据：结论证据覆盖率、引用可解析率、无依据结论率。
- 合规：高风险召回率、误报率、正确转人工率。
- 运行：成功率、P50/P95 延迟、平均 token/成本、重试率。
- 选品：时间切分后的 Precision@K、NDCG@K、实际毛利/订单表现和基线对比。

### 11.3 发布门槛

关键测试必须全部通过；高风险合规漏检、跨组织数据泄漏、无审批写操作和不可恢复的工作流中断属于阻断问题。其余量化门槛在基线评测完成后写入版本化评测配置，避免在没有实测前虚构达标数字。

## 12. 验收标准

完整交付须同时满足：

1. 九个 Agent 均有明确结构化协议、可执行工作流和至少一条端到端业务链路验证。
2. 支持自动连接器接口与原始报表导入，用户不需要手工重写广告表格。
3. 广告诊断、真实利润、选品回测、库存供应、客户素材和合规能力均可在管理端操作或查看。
4. 高影响建议进入人工审批，重启后可恢复，审计记录完整。
5. 指标计算、权限、连接器契约、工作流和核心前端流程具备自动化测试。
6. 至少 80 条 AI 评测案例可重复运行并输出报告。
7. Docker Compose 可启动开发所需服务，README 包含安装、演示和架构说明。
8. 演示数据全部脱敏或合成；仓库不包含真实凭证、商家隐私或未经许可的素材。

## 13. 对外描述边界

- 可以描述为“以外部技术合作伙伴身份，为跨境电商业务设计并开发多 Agent 经营决策系统”。
- 只有完成并验证的能力才能写入简历成果；性能、准确率、节省时间和业务提升必须来自可复现测试或真实项目记录。
- 未获得平台生产权限时，只能描述“完成连接器架构、模拟接入和导出报表兼容”，不能描述为“已接入生产 TikTok 商家账户”。
- 项目关系不得写成朋友公司的正式员工经历，可写为项目合作、外部技术合作伙伴或独立开发者。
